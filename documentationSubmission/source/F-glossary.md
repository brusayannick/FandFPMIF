# Glossary

**Activity**: the label identifying what happened in an event. **Case**: one process instance. **Event**: one recorded occurrence, minimally a case identifier, an activity and a timestamp. **Trace**: the ordered sequence of events belonging to one case. **Variant**: the set of traces sharing the same activity sequence. **Resource**: the actor, human or system, that executed an event.

**Event log**: an ordered, case-attributed collection of events; the input to every process mining technique. **XES**: IEEE 1849, the XML interchange standard for event logs, carrying its own attribute semantics. **OCEL (object-centric event log)**: a log representing events, objects and their relations rather than case-attributed traces. **Parquet**: the columnar file format in which normalised event data is stored.

**Discovery**: deriving a process model from a log without any a priori model. **Conformance checking**: comparing a model with a log to detect and quantify deviations. **Enhancement**: repairing or extending an existing model using the log. **Fitness, precision, generalisation, simplicity**: the four competing dimensions along which a discovered model's quality is judged. **Concept drift**: a process changing while it is being analysed, so that one log contains behaviour from several process versions.

**Directly-follows graph (DFG)**: a graph with one node per activity and an edge wherever one activity was observed directly after another. **Petri net**: a model of places and transitions expressing concurrency, choice and synchronisation. **Process tree**: a hierarchical model composing sub-trees with sequence, choice, parallel and loop operators; sound by construction.

**Throughput**: cases completed per unit of time. **Lead time (cycle time)**: the elapsed time from a case's first to its last event. **Sojourn time**: the time an activity occupies; distinguished from **waiting time**, the interval between one activity completing and the next starting, only when events carry both a start and an end timestamp.

**Module**: a self-contained folder the platform discovers, isolates and mounts, contributing analysis, routes and interface without any change to the platform. **Manifest**: `manifest.yaml`, the declarative registration of a module. **Module context**: the Protocol-typed object every handler receives, exposing data access, a scoped cache, configuration, progress reporting, the bus, the registry, a logger and a scratch directory. **Panel**: a module's own user interface, bundled separately from the main application build and constrained to an allow-list of platform imports. **Isolation level**: whether a module runs inside the platform's interpreter (`in_process`) or in its own worker process on its own interpreter (`subprocess`). **Worker bridge**: the Unix-socket JSON-RPC channel, with a Parquet handoff for bulk data, connecting the platform to a module running in a separate process or a non-Python runtime. **Sidecar**: an optional service container, enabled by a compose profile, that a module connects to when it needs a whole server rather than a library.

**Job**: a persisted, observable, cancellable unit of long-running work; the platform's only mechanism for anything that can outlast a request. **Event bus**: the in-process publish-and-subscribe channel carrying platform and module events; bounded per subscriber, dropping the oldest event when a queue is full. **Capability registry**: the typed request-and-response mechanism by which one module calls another. **Precompute closure**: the transitive set of modules a freshly imported log waits for, frozen at import time and derived from the declared graph of published and consumed topics. **Readiness gate**: the mechanism holding a log in `processing` until every module in its precompute closure reaches a terminal state.

**Tenant isolation**: the invariant that every artefact belonging to a user is keyed by that user's identity claim, at rest and in flight. **Server-Sent Events (SSE)**: the one-directional HTTP streaming transport carrying live updates to the browser, chosen because the production proxy chain does not carry WebSocket upgrades.
